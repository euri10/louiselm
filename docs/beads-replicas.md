# Session Beads replicas

The installed broker uses the one administrator-selected canonical project in
`/etc/louiselm-broker-beads.json`. A launch grant must bind that project's digest
before the Session receives its replica. Provisioning alone grants no tracker
mutations or graph disclosure. Without provisioning or a project-bound grant,
ordinary launch remains available and no replica mount is added.

Canonical `.beads` denies all access to identities outside its operator/broker
owners and broker group. Provisioning rejects other-user permission bits on
that directory, as well as the existing untrusted ownership, links and extended
ACL cases. The Agent and its confined tools cannot open the canonical database
or JSONL, even when its parent is otherwise visible in their namespace.

The broker exports with the pinned upstream `br`, builds a new local database
with that same binary, and stages the complete closed database family. No
SQLite schema or graph semantics are implemented in LouiseLM. Process locks are
regenerated by the consuming Session; WAL, journal and durability-certificate
data remain together. The launcher checks the exact launch binding, installs
the initial copy under the private Session root, and supplies `BEADS_DIR` to
both the Agent and its confined tools. Native commands need no extra flags.

Each replica generation is writable by its Session because native `br` reads
need local locks and SQLite maintenance. The generation is disposable and is
not trusted evidence of canonical state. A local `br update`, replacement file,
or edited JSONL affects only that replica. Canonical writes require the existing
authenticated typed broker request and its exact effect permission.

The containing publisher directory and `current` pointer remain broker-owned
and not writable by the Session. After a successful canonical mutation, the
broker builds a fresh generation in private storage and atomically selects it
before returning the existing durable mutation receipt. It never reads an old
Session-writable generation. Existing readers may finish on the old generation;
subsequent native invocations resolve the new one. Old generations remain until
Disposal, bounded by the Session's mutation-attempt budget plus its initial copy.
One generated snapshot is limited to 256 entries and 256 MiB.

A publication failure does not undo a completed canonical mutation. Retrying
the same request uses the retained mutation outcome and repairs publication
without executing the mutation again. A completed replay never selects an older
generation over a newer one. Recovery after the pointer rename needs only
publisher-owned metadata, never an inspection of the Session's edited database.
Unknown or failed mutation outcomes do not claim that a fresh replica exists.

Broker restart discards abandoned private launch staging; running Sessions keep
their already-mounted replicas. Warm Park retains the replicas with the Session.
Disposal first proves the process trees gone and seals the Session root, then
removes all replica generations without following links. Cleanup failure is
reported before identity reuse. Source/cache Forensics retention remains a
separate lifecycle. A new Session receives a fresh replica from canonical state.

The real-upstream regression is
`broker::beads_replica::tests::real_br_replica_preserves_native_reads_after_refresh`.
Run it through `scripts/test-skills-core` outside an ACP subreaper, with explicit
`LOUISELM_TEST_BR` and optional `LOUISELM_TEST_BVR` paths and `--ignored`.
The existing required installed tracker gate additionally probes actual file
opens inside the measured Agent's namespace and native reads under its assigned
UID. Automated acceptance uses disposable projects and no credentials or network;
it does not activate tracker mediation on the maintainer's desktop.
